# 予定時刻ミス検知カレンダー

保存するだけの普通のカレンダーと違い、**保存時に時刻の妥当性を検証する**カレンダーアプリ。
「20:00 のつもりが 2:00 と入力されていた」といった入力ミスや、典型的な時間帯・所要時間から
外れた予定を検知し、保存をブロックせずに黄色い警告で知らせる。詳細は
`CALENDAR_VALIDATION_SPEC_2.md`（実装指示書）を参照。

## スタック

- React 19 + TypeScript + Vite
- ブラウザの IndexedDB（データはこの端末・このブラウザ内にのみ保存。アカウント登録不要）
- date-fns（日付計算）
- Vitest（バリデーション・プランナー・同期ロジックの単体テスト）
- Google Identity Services + Google Calendar API v3（Googleカレンダー同期）
- Claude API（`@anthropic-ai/sdk`、AIプランナー）

データは基本的にその端末・ブラウザだけに保存される。「設定」でネット保存の合言葉を入れると、
Vercel 上の保存場所にも保存され、他の端末や Claude からも読み書きできる(後述)。複数端末で同期したり、
バックエンドに保存したい場合は `supabase/migrations/0001_init.sql` に Supabase 版のスキーマ
（`events` / `categories` テーブル、認証、ストレージ）を用意してあるので、そちらに切り替える
ことも可能。

## バリデーションロジック

`src/lib/validation/` にUIから完全に独立した純粋関数として実装している。

```ts
validateEvent(event: EventInput, userHistory: EventInput[], now?: Date): Warning[]
```

- R1 桁落ち検知（`2:00` → `20:00` の打ち間違い提案）
- R2 深夜帯フラグ（0:00〜4:59）
- R3 カテゴリ別の典型時間帯チェック（過去5件以上の実績があれば10〜90パーセンタイルで算出、なければデフォルト値）
- R4 所要時間の妥当性（標準所要時間の0.5〜3倍から外れる場合）
- R5 根拠なしフラグ（`hasNoEvidence()` — ダイアログは出さず、一覧のフィルタでのみ使用）
- R6 遠い未来（60日以上先）の予定は R1/R3/R4 の閾値を厳しめにし、添付を促すリマインダーを追加

保存はブロックせず、警告は「〇〇に修正する」／「このままで合っています」で解消し、
イベントの `warnings` に履歴として記録する。一度「合っています」を選ぶと `time_confirmed`
が立ち、時刻を変更しない限り同じ警告は再表示されない。

`memory_checked_at` / `miss_count` フィールドは、将来の記憶テスト機能のために予約されている
（今回は未使用）。

## データの保存先

`src/lib/localDb.ts` がブラウザの IndexedDB を薄くラップしている。予定は `events`
オブジェクトストア、カテゴリは `categories` オブジェクトストアに保存される。チケット画像は
Blob としてそのままレコードに保存する（外部ストレージ不要）。

ブラウザのデータを消去する（プライベートブラウジングを終了する、サイトデータをクリアする等）
と保存した予定も失われる点に注意。

## 既存カレンダーからのインポート

画面上部の「インポート」から、Googleカレンダー等からエクスポートした `.ics` ファイルを
読み込んでまとめて取り込める（`src/lib/icsImport.ts`）。取り込み時は一括で1つのカテゴリを
指定し、個々の予定はチェックボックスで選別できる。バリデーション（R1〜R6）は手入力時のみ
発火する設計のため、インポート時は警告ダイアログを出さずそのまま保存する。

## Googleカレンダー同期

画面上部の「Google同期」で、Googleカレンダーと**双方向**に同期する（`src/lib/google/`）。

- 対象期間は「今日の30日前〜180日後」。繰り返し予定は1回ずつに展開して取り込む。
- Googleにだけある予定 → このアプリに追加 / このアプリにだけある予定 → Googleに追加
- 片方で編集・削除した予定は、もう片方にも反映する。両方で編集していたら更新時刻が新しいほうを採用する。
- 差分の判定は `computeSyncPlan()`（副作用なしの純粋関数）に分けてあり、単体テストがある。

### 準備（初回のみ）

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「Google Calendar API」を有効にする。
2. 「APIとサービス → OAuth 同意画面」を設定し、自分のGoogleアカウントをテストユーザーに追加する。
3. 「認証情報 → OAuth クライアントID」を「ウェブアプリケーション」で作成し、
   「承認済みの JavaScript 生成元」にアプリのURL（開発時は `http://localhost:5173`）を追加する。
4. 発行されたクライアントIDを、アプリの「設定」に入力するか、`.env.local` に
   `VITE_GOOGLE_CLIENT_ID=xxxx.apps.googleusercontent.com` と書く。

バックエンドを持たないため、ログインは Google のポップアップで行い、短時間だけ有効なアクセストークンを使う
（ページを開き直すと再度許可を求められることがある）。

## 今日のTodo（AIプランナー）

「今日のTodo」タブで、締切のあるタスク（レポート・テスト勉強など）を登録すると、
カレンダーの予定を避けた空き時間に「今日どの時間に何をやるか」を割り当てる（`src/lib/planner/`）。

- **AIで今日の計画を立てる**：Claude（`claude-opus-5-5`）が、締切・残り時間・優先度・メモ・空き時間をもとに計画を立てる。
  AIの出力は `sanitize()` で検証し、空き時間の外や重なっている作業は捨てる。
- **AIなしで自動割り当て**：APIキー不要。締切の近い順に、休憩を挟んで空き時間に並べる。

どちらも共通の `buildPlanningContext()` で「今日やらないと締切に間に合わない分」を計算している。
締切の遅いタスクから順に、締切日からさかのぼって空き時間に詰めていき（遅延スケジューリング）、
それでも今日にはみ出した分が「今日の必須分」になる。空き時間が足りずどうしても終わらない場合は警告を出す。

計画の各行をチェックすると、そのぶんタスクの進捗が進む。「この計画をカレンダーに入れる」で作業ブロックを
予定として追加でき、Google同期すれば Google カレンダーにも入る。

AIプランナーを使うには「設定」で Claude の APIキー（[Claude Console](https://platform.claude.com/) で発行）を入力する。
キーはこのブラウザの localStorage にだけ保存され、ブラウザから Anthropic の API に直接送られる。
個人利用向けの方式なので、共有PCでは入力しないこと。

## ネット保存(スマホ・PC・Claude で共有)

`api/data.ts` が Vercel Function として動き、データを Vercel Blob(非公開)に JSON 1ファイルで保存する。

- `GET /api/data` … 全データ / `POST /api/data {"ops": [...]}` … 変更(追加・更新・削除)を適用
- どちらも `Authorization: Bearer <APP_TOKEN>` が必要。APP_TOKEN は Vercel のプロジェクトの環境変数
- 同時に書き込んでも取りこぼさないよう、Blob の ETag を使って「読んだときから変わっていなければ書く」をくり返す
- 変更の形(op)と適用は `api/_lib/cloudDoc.ts`(サーバーとアプリで共通の純粋関数)

アプリ側(`src/lib/cloud/cloudSync.ts`)は端末の IndexedDB をそのまま使い、変更を「送信待ち」に貯めてから送る。
アプリを開いたとき・画面に戻ったとき・1分ごとに最新を取りに行く。初めて合言葉を入れた端末は、
端末にあってネットにないデータを送る。

### 準備

1. Vercel のプロジェクト → Storage → Create → Blob を **Private** で作り、このプロジェクトにつなぐ
   (`BLOB_READ_WRITE_TOKEN` が自動で入る)。つないだあと再デプロイする
2. プロジェクトの環境変数に `APP_TOKEN`(合言葉)を入れる
3. アプリの「設定」→「ネット保存」に同じ合言葉を入れる

手元から読み書きするときは `CLOUD_TOKEN=<合言葉> node scripts/cloud.mjs get` など。
