# 予定時刻ミス検知カレンダー

保存するだけの普通のカレンダーと違い、**保存時に時刻の妥当性を検証する**カレンダーアプリ。
「20:00 のつもりが 2:00 と入力されていた」といった入力ミスや、典型的な時間帯・所要時間から
外れた予定を検知し、保存をブロックせずに黄色い警告で知らせる。詳細は
`CALENDAR_VALIDATION_SPEC_2.md`（実装指示書）を参照。

## スタック

- React 19 + TypeScript + Vite
- ブラウザの IndexedDB（データはこの端末・このブラウザ内にのみ保存。アカウント登録不要）
- date-fns（日付計算）
- Vitest（バリデーションロジックの単体テスト）

データはサーバーに送信されず、その端末・ブラウザだけに保存される。複数端末で同期したり、
バックエンドに保存したい場合は `supabase/migrations/0001_init.sql` に Supabase 版のスキーマ
（`events` / `categories` テーブル、認証、ストレージ）を用意してあるので、そちらに切り替える
ことも可能。

## セットアップ

```sh
npm install
npm run dev
```

これだけで起動する。アカウント登録や環境変数の設定は不要。

## スクリプト

- `npm run dev` — 開発サーバー
- `npm run build` — 型チェック + 本番ビルド
- `npm run test` — バリデーションロジックの単体テスト（Vitest）
- `npm run lint` — Oxlint

## バリデーションロジック

`src/lib/validation/` にUIから完全に独立した純粋関数として実装している。

```ts
validateEvent(event: EventInput, userHistory: EventInput[], now?: Date): Warning[]
```

- R1 桁落ち検知（`2:00` → `20:00` の打ち間違い提案）
- R2 深夜帯フラグ（0:00〜4:59）
- R3 カテゴリ別の典型時間帯チェック（過去5件以上の実績があれば10〜90パーセンタイルで算出、なければデフォルト値）
- R4 所要時間の妥当性（標準所要時間の0.5〜3倍から外れる場合）
- R5 根拠なしフラグ（`hasNoEvidence()` — ダイアログは出さず、一覧のフィルタでのみ使用）
- R6 遠い未来（60日以上先）の予定は R1/R3/R4 の閾値を厳しめにし、添付を促すリマインダーを追加

保存はブロックせず、警告は「〇〇に修正する」／「このままで合っています」で解消し、
イベントの `warnings` に履歴として記録する。一度「合っています」を選ぶと `time_confirmed`
が立ち、時刻を変更しない限り同じ警告は再表示されない。

`memory_checked_at` / `miss_count` フィールドは、将来の記憶テスト機能のために予約されている
（今回は未使用）。

## データの保存先

`src/lib/localDb.ts` がブラウザの IndexedDB を薄くラップしている。予定は `events`
オブジェクトストア、カテゴリは `categories` オブジェクトストアに保存される。チケット画像は
Blob としてそのままレコードに保存する（外部ストレージ不要）。

ブラウザのデータを消去する（プライベートブラウジングを終了する、サイトデータをクリアする等）
と保存した予定も失われる点に注意。

## 既存カレンダーからのインポート

画面上部の「インポート」から、Googleカレンダー等からエクスポートした `.ics` ファイルを
読み込んでまとめて取り込める（`src/lib/icsImport.ts`）。取り込み時は一括で1つのカテゴリを
指定し、個々の予定はチェックボックスで選別できる。バリデーション（R1〜R6）は手入力時のみ
発火する設計のため、インポート時は警告ダイアログを出さずそのまま保存する。
